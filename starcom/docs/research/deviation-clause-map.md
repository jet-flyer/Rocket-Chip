## How to read this file

- Each row maps one stated project item to one book clause.
- The "quoted text" column is a direct quote from the book. Nothing in that column is a paraphrase.
- The "shall/should/may" column lists the keyword that appears in the quote. It uses the book wording exactly.
- If a quote has no keyword, the column says "none" and gives the reason.
- The book defines its keywords in 732.1-B-3 §1.6.2.1, p. 1-5 to 1-6: "the words ‘shall’ and ‘must’ imply a binding and verifiable specification"; "the word ‘should’ implies an optional, but desirable, specification"; "the word ‘may’ implies an optional specification"; "the words ‘is’, ‘are’, and ‘will’ imply statements of fact."
- 732.1-B-3 §1.6.2.2, p. 1-6, says: "In the normative sections of this document, informative text is set off from the normative specifications either in notes or under one of the following subsection headings: – Overview; – Background; – Rationale; – Discussion." 232.0-B-4, 132.0-B-3, and 355.0-B-2 have the same rule (§1.x). I did not find this rule in 232.1-B-2.
- Text marked **INFERENCE** is my reasoning. It is not a quote. Text that is not marked INFERENCE is a quote or a checked fact.
- "Starcom parallel" is copied from the survey summary table (survey lines 252–269). If the summary table does not name a parallel for that item, the cell says "none named".

## B-2 vs B-3 diff note (732.1)

Method: I took both texts with pdftotext -layout. I removed page headers and footers. I ran a line diff on the sections below. B-2 source: Wayback capture of public.ccsds.org/Pubs/732x1b2.pdf (cover: "CCSDS 732.1-B-2 BLUE BOOK October 2021", "Issue: Recommended Standard, Issue 2").

### Same text in B-2 and B-3 (only line wrap or cross-reference numbers differ)

- §2.1.2.5 SDLS (optional), p. 2-4 in both. Same text.
- §6.2 Use of SDLS, p. 6-1 in both. Same "shall" text.
- §6.3.3 Insert Zone in a frame with SDLS, p. 6-2 in both. Same.
- §6.3.4 Security Header, p. 6-2 in both. Same "shall" text. B-2 NOTE 3 ends "managed parameter of the VC". B-3 NOTE 3 ends "managed parameter of the MAP or VC".
- §6.3.5.2 TFDF with SDLS, p. 6-3 in both. Same.
- §6.3.6 Security Trailer, p. 6-3 in both. Same "shall" text. B-2 NOTE 1 says "a managed parameter of the VC (see 6.6)". B-3 NOTE 1 says "a managed parameter of the VC or MAP (see 6.6)".
- §6.3.7.2 OCF with SDLS: B-2 p. 6-3, B-3 p. 6-4. Same.
- §6.3.8.2 FECF with SDLS, p. 6-4 in both. Same.
- §4.1.3 Insert Zone, p. 4-10 in both. Same.
- Table 5-1 note 5 ("Insert Zone may only be present when Physical Channel Frame Type is equal to Fixed Length."), p. 5-2 in both. Same.
- §4.1.2 Primary Header (all fields), p. 4-2 to 4-9 in both. Normative text is the same. Only the cross-references changed ("4.3.10.3" to "4.3.11.3"; "3.9.2.4"/"3.6.2.4" to "3.11.2.4"/"3.8.2.4"). This covers Source-or-Destination (§4.1.2.3), MAP ID (§4.1.2.5), the Protocol Control Command Flag (§4.1.2.8.2), the VCF Count Length (§4.1.2.11), the VCF Count (§4.1.2.12), and NOTE 4 on TC/Prox-1 counts.
- §4.1.6 FECF: no diff.
- Insert SDU clause: same text. The number changed from §3.2.7 (B-2) to §3.2.8 (B-3).

### Changed in B-3

1. **SDLS per MAP (new).** B-2 §6.1: "it has managed parameters for each VC to indicate whether SDLS is in use for that channel". B-3 §6.1: "for each VC or each MAP". B-3 adds Table 6-3 "Additional Managed Parameters for a MAP When TC Space Data Link Protocol Supports SDLS" (p. 6-15). B-2 has only Table 6-1 (VC, p. 6-9).
2. **Protocol control frames carry no SDLS fields (new sentence, Overview §6.3.1, p. 6-1).** B-3: "Transfer frames containing protocol control information, that is, Protocol Control Command Flag in the Transfer Frame Primary Header set to ‘1’, do not contain the Security Header and Security Trailer and are therefore not protected by SDLS." This sentence is not in B-2. It is Overview text (informative).
3. **Order of processing USLP/COP/SDLS (new).** B-3 §6.4.2.1, p. 6-5: "In the Virtual Channel Generation Function at the sending end, the order of processing between the functions of the USLP, COP, and SDLS protocols shall occur as follows: a) the Frame Initialization Procedure including SDLS; b) the SDLS ApplySecurity Function; c) the FOP ... ; d) the Frame Finalization Procedure including SDLS." B-2 §6.4.4.3 b), p. 6-5, had only two steps: "1) the USLP Frame assembly processing by the VC Generation Function; 2) the call by the VC Generation Function to the SDLS ApplySecurity Function." B-3 also adds Table 6-1 and Figure 6-2 (order of processing).
4. **New services.** B-3 adds §3.4 VC Packet Service and §3.6 VC Access Service. B-2 §3.4 (MAPA) became B-3 §3.5. B-2 §3.5 to §3.10 became B-3 §3.7 to §3.12. PICS item numbers moved (for example, B-2 "USLP-6 Insert Data SDU" became B-3 "USLP-7"; B-2 "USLP-127 SDLS Protocol" became B-3 "USLP-151").
5. **TFDZ rules.** B-3 §4.1.4.2.2.1.3 (p. 4-13): "A MAPA_SDU, a VCA_SDU, or a single Packet SDU may be segmented ... within the same SAP, that is, GMAP ID (for MAPs) or GVCID (for VCs)." B-2 §4.1.4.2.2.1.3 (p. 4-13): "A MAPA_SDU and/or a single Packet SDU may be segmented ... within the same GMAP ID (VCID +_ MAP ID)." Rule ‘111’ (§4.1.4.2.2.2.8) adds "b) one VCA_SDU". Rules ‘001’ and ‘010’ add VCA_SDU.
6. **Managed parameters.** Table 5-1, "Maximum Number of Transfer Frames Given to the ... Sublayer as a Single Data Unit": B-2 value "1", B-3 value "Integer". Table 5-3 adds "SDU Type (Data Field Content) CCSDS Packet, VCA_SDU". Table 5-2 SCID: B-2 "16-bit Integer", B-3 "Integer (0 to 65535)".
7. **Truncated frame reference.** §6.3.2.2: B-2 "D1.3", B-3 "D1.2.5".

### What this means for each project (INFERENCE, labeled)

- OreSat: the clauses behind both "out of spec" notes (§6.3.4, §6.3.6) have the same text in B-2 and B-3. Citing B-2 does not change the finding. The Protocol Control Command Flag text (row 18) is also the same in both.
- spacepackets-py (B-2): the Primary Header text did not change. The changes that can matter are the VCP and VCA services, the VCA_SDU in the TFDZ rules, and per-SAP segmentation. I did not review the library code.
- CryptoLib: it does not claim USLP. If someone uses it for USLP against B-3, the per-MAP SDLS, the PCC=1 rule, and the §6.4.2 order of processing are the B-3 additions to check.
- Yamcs (cites B-2): B-3 adds the VCP service (§3.4). B-2 has no VC-level packet service. I did not check how Yamcs maps its USLP "packet service" to a B-2 or B-3 service.
